# Безопасность и работа с секретами

## Модель угроз

| Угроза | Защита | Проверено |
| --- | --- | --- |
| Приватный ключ в открытом виде на диске | AES-GCM, ключ в Android Keystore (не экспортируется) | код + отсутствие ключей в `adb logcat` |
| Ключ в логах / crash reports | `Diagnostics.scrub` редактирует ключи, токены, `?token=` | 6 юнит-тестов |
| Ключ в UI-состоянии / saved state | `VpnProfile` **не содержит** конфиг; он читается только при старте туннеля | архитектурно |
| Токен в URL утекает в логи | в диагностику идёт только SHA-256 hint (4 байта) | `hint is stable and does not reveal the token` |
| Конфиг в deep link | в ссылке только opaque-токен, не конфиг | `DeepLinkHandler` |
| Открытый редирект / подмена хоста | строгая проверка scheme + host, иначе `Rejected` | 8 тестов |
| Произвольные команды из deep link | ссылка не исполняет ничего; только `ImportRequest` | архитектурно |
| Утечка трафика при проверке связи | проба идёт через активный VpnService, не в обход | архитектурно |
| Автозапуск незнакомого профиля по ссылке | туннель стартует только по явному нажатию | архитектурно |
| Битый/огромный конфиг | лимит 64 КБ, запрет control-символов, структурная проверка | `oversized config is rejected`, `control characters are rejected` |

## Хранение секретов

```
SharedPreferences "vpn_profiles"        ← метаданные (имя, протокол, endpoint). Без секретов.
SharedPreferences "vpn_secure_configs"  ← ТОЛЬКО шифртекст AES-GCM + IV
Android Keystore "myvpn_config_key_v1"  ← AES-256, non-exportable, TEE/StrongBox
```

`setUserAuthenticationRequired(false)` выбран осознанно: VPN должен уметь подняться
в фоне (после перезагрузки) без разблокировки приложения. Компромисс: на
разблокированном устройстве с root злоумышленник может расшифровать конфиг через
само приложение. Альтернатива (требовать биометрию) ломает автоподключение.

Если ключ инвалидирован (сброс device credential), `getConfig` вернёт `null` и
удалит непригодную запись — пользователю предлагается импорт заново, а не тихий
сбой.

## Что НЕ делается

- Секреты не коммитятся: `.gitignore` исключает `local.properties`, `*.keystore`,
  `*.jks`, `app/libs/*.aar` собирается локально.
- TLS-проверки не отключались нигде (сетевого слоя, кроме пробы, пока нет).
- Приватные ключи не уходят на сервер и не покидают устройство.

## Открытые вопросы

1. **`allowBackup="false"`** — бэкап отключён, чтобы шифртекст не уезжал в облако.
2. **Серверная авторизация** — не реализована. Когда появится backend, он обязан
   проверять токен на сервере, а не доверять клиенту.
3. **Обнаруженные ранее секреты** — в этом проекте не найдено. Токены
   инфраструктуры (GitHub, Zabbix, SSH) в код не попадали; они читались из
   существующих хранилищ окружения и в отчёты не выводились.
