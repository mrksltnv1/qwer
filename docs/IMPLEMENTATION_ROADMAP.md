# Roadmap внедрения (после аудита v0.8.9)

Источник приоритетов: `docs/COMPETITIVE_ANALYSIS.md`.
Правило: одна задача = один MR, тесты вместе с кодом, релиз после зелёного CI.

## Статус реализации (2026-10-24)

Закрыто: P0-1, P0-2, P0-3, P1-1, P1-2, P1-3, а также кодек QR и модель per-app
маршрутизации из P2. Проверено: 212 тестов, 0 провалов, `BUILD SUCCESSFUL`.
Отчёт: `REPORT.md`.

Отклонения от плана (сознательные, с причинами):

| Пункт | По плану | Сделано | Почему |
|---|---|---|---|
| P0-1 | `DeviceReport.kt`, `DeviceChecks.kt` | `DeviceProbe.kt`, `DiagnosticRules.kt`, `DiagnosticModels.kt`, `DiagnosticEngine.kt` | разделение «сбор фактов» / «правила» / «модель» позволило тестировать правила без устройства |
| P0-1 тесты | 6 | 22 | правил оказалось больше, каждое проверяется отдельно |
| P0-2 | `EngineFailureTest` | `EngineErrorMapperTest`, 17 тестов | покрыты все `Reason` + неизвестная + граничные случаи |
| P0-3 | `BackupModel.kt` | `BackupPayload.kt` | имя отражает суть: это разбор полезной нагрузки, а не модель UI |
| P0-3 тесты | 8 | 29 (17 + 12) | добавлены лимиты, AAD, границы итераций |
| P1-1 | `count` в записи `Diagnostics` | группировка на отображении | группировка при записи теряет детали, нужные для разбора инцидента |
| P1-2 | `StartRequestGate` | `OperationGate`, 11 тестов | имя шире: гейт защищает не только старт сервиса |
| P2 QR | `QrCodec` + zxing | только `QrCodec` | формат и целостность готовы и покрыты; рендеринг/камера требуют зависимости и разрешений — отдельная задача |
| P2 per-app | VPN/DIRECT/BLOCK | `All` / `Only` / `Except` | Android поддерживает ровно два взаимоисключающих механизма; режим BLOCK выразить нечем |

Незакрытое: UI выбора приложений, UI и камера для QR, восстановление статистики
сессии, P3.

## P0 — сейчас

### P0-1. Диагностика устройства
- [ ] `device/DeviceReport.kt` — data class + сбор
- [ ] `device/DeviceChecks.kt` — чистые проверки (ABI, SDK, 16 КБ страницы, память, native libs, разрешение уведомлений, статус FGS)
- [ ] `ui/DiagnosticsScreen.kt` + пункт в меню
- [ ] Кнопка «Скопировать отчёт»
- [ ] `DeviceChecksTest` — 6 тестов
- **Готово когда:** отчёт копируется, при отсутствии WDTT пишет «не установлен», а не «ошибка»
- **Модули:** новый `device/`, `ui/`, `MainActivity`
- **Откат:** убрать пункт меню

### P0-2. Ошибки движка по стадиям
- [ ] `EngineFailure` (sealed) в `core/`
- [ ] `TunnelEngine` пробрасывает `BackendException.Reason`, не строку
- [ ] Заменить `humanEngineError`
- [ ] `EngineFailureTest` — 9 тестов (все Reason + неизвестная)
- **Готово когда:** каждая причина из AAR имеет человеческий текст; неизвестная не теряется
- **Модули:** `core/ConnectionManager`, `engine/TunnelEngine`
- **Откат:** старый метод оставить `@Deprecated` на один релиз

### P0-3. Шифрованный бэкап профилей
- [ ] `backup/BackupCodec.kt` — AES-GCM + PBKDF2WithHmacSHA256 (>= 210k итераций)
- [ ] `backup/BackupModel.kt` — версия формата + профили
- [ ] `ui/BackupScreen.kt` — экспорт/импорт через SAF
- [ ] `BackupCodecTest` — 8 тестов (round-trip, неверный пароль, обрезка, подмена AAD, лимит)
- **Готово когда:** экспорт→импорт на чистой установке восстанавливает профили и активный
- **Модули:** новый `backup/`, `secure/`, `ui/`
- **Откат:** формат версионирован; отключить пункт меню

## P1 — после P0

### P1-1. Группировка логов
- [ ] `Diagnostics` хранит `count` у записи
- [ ] Схлопывание только соседних записей с одинаковым event+ключами

### P1-2. Generation-защита старта сервиса
- [ ] `StartRequestGate` (next/invalidate/isCurrent)
- [ ] Встроить в `ConnectionForegroundService` + `ConnectionManager`
- [ ] `StartRequestGateTest` — 5 тестов

- [ ] Тест на «нет данных ≠ ноль»
- **Готово когда:** UI не показывает `0 B`, когда движок недоступен
